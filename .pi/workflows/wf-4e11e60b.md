6. **The three optimizer passes (emit_c_lower.lua) operate on raw CBackendBlocks**: copy propagation, dead copy elimination, and field hoisting. They are structural, local-block optimizations that know nothing about loops or dataflow across blocks. They run as a post-processing step in `c_emit_func`, after lowering.

7. **Carrier/address plans create synthetic blocks** — both `code_to_c.lua` and `lower_to_c.lua` inject `edge_transfer_blocks` (temp blocks for arg computations) when carrier/address state needs to be threaded between real blocks. These are synthesized by functions like `edge_transfer_dest`.

8. **The pipeline has two convergent paths**: `LowerEmitCode` (baseline) calls `CodeToC`'s block lowering which is purely structural. `LowerEmitScalarKernel` builds fresh CBackendBlocks from CMat materialization. Both output to the same `c_emission.blocks` array, which are merged into the final function body.

9. **Stencil computations are compiled twice**: once inline (via CMat → CBackendStmts in lower_to_c.lua), and once as standalone functions (via stencil_c.lua). The standalone stencil path gets restrict + assume_aligned; the inline path only gets restrict (and only on function params, not local pointers).
