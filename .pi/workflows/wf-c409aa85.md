## Relationships

- `NativeCompleteBankCapability:native_template_sources()` / `NativeTemplateSupportDomain:native_template_sources()` call `build_sources_*` in `lua/lalin/native_template_sources.lua`.
- Concrete ASDL leaf methods like `Native.NativeCodeMicroOpBinaryShape:append_native_template_sources`, `Native.NativeStencilProducerRange1DShape:append_native_template_sources`, etc. append `NativeTemplateSource` values to an output list.
- Each source builder:
  1. constructs `holes`,
  2. builds `lines` as strings,
  3. calls `append_manifest_source`,
  4. `concat_lines(lines)` becomes `NativeTemplateSource.c_text`.
- `tools/gen_lalin_mc_bank.lua` later writes that `c_text` to a `.c` file and compiles it offline.
- Runtime native path consumes compiled bank artifacts; docs explicitly state runtime does not compile C.
- `llbl.c` already has the LLBL surface mechanics to build C-ish object trees and render them, but native source generation does not use it.
- `lua/lalin/stencil_c.lua` is an existing example of using `llbl.c` as an object-tree C generator, ending in:

```lua
return C.emit_unit(C.unit. lalin_stencil_unit {
    _(LLBL.fragment("decls", decls)),
}, opts)
```

## Observations

- `llbl.c` is currently a shallow LLBL dialect over Lua tables, not ASDL-backed.
- Current `llbl.c` renderer and formatter both dispatch by `kind` strings.
- `llbl.c` has useful alignment with LLBL mechanics: roles, heads, fragments, splicing with `_`, curried ops, format hooks.
- Raw escape hatches exist for expr/stmt/decl/param.
- Native source generation uses many C constructs not first-class in current `llbl.c`: `extern` function declarations/prototypes, extern variables, inline asm, arbitrary `typedef` function pointers, `volatile` declarations/qualifiers, `sizeof`, GCC atomics, `memcpy`/`memset` builtins, function declarations without bodies, public ABI prototypes, struct declarations without typedef-like constraints, and statement-level declarations inside generated function bodies.
- Current `llbl.c` covers includes, defines, typedefs, typedef structs, functions with bodies, static/static inline functions, declarations, assignment, return, if/else, for, while, expression statements, casts, compound literals, initializer lists, GNU `typeof`, GNU statement expressions, vector attributes, builtins, pointer/array/function-pointer types.
- `tests/code_ir/test_native_template_sources.lua` encodes many expected C-text substrings, so a rework that changes formatting/content would hit tests that assert exact/source substring behavior.
- Docs identify `lua/lalin/native_template_sources.lua` as “ASDL leaf-owned C-stencil source generation,” separate from `lua/lalin/c_emit.lua` / `lower_to_c.lua` C backend.
