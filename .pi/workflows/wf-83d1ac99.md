## Relationships

- Public `lalin.compile()` defaults to `compile_native()` unless `opts.luajit` or `opts.bytecode` is true.
- `compile_native()`:
  - builds Tree via `module_ast_from`,
  - runs `frontend_pipeline.typecheck_module`,
  - runs `frontend_pipeline.checked_to_code_result`,
  - calls `native_backend.compile_code_module(code_result.module, target, runtime, bank, manifest)`.
  - Requires prebuilt `NativeTemplateBank`/`NativeEmbeddedTemplateBank`.
- `emit_luajit_artifact()`:
  - also runs `typecheck_module` and `checked_to_code_result`,
  - then `luajit_backend.lower_module`,
  - emits bytecode artifact via `luajit_backend.emit_lua_artifact`.
- `emit_c_artifact()` currently uses the LuaJIT path:
  - `prepare_luajit_artifact`,
  - `luajit_emit.emit_c_artifact(plan.lj_module, ...)`,
  - returns `LuaJITCSourceArtifact`.
- `Decl:lower()` does **not** use `emit_c_artifact`; it calls `compiler_driver.lower_module`, which uses `compiler_package` and phase execution to produce `LalinC.CBackendUnit`.
- `frontend_pipeline.code_result_to_c()` and `lower_to_c.lua` are active through `compiler_machines.code_to_c` / phase package / `Decl:lower()` tests, but they are not the public `emit_c_artifact` implementation.
- `frontend_pipeline.code_result_to_back()` and `lower_to_back.lua` exist and are exported, but search found no public root/package use except direct tests and module exposure.
