```lua
function G.GccJitTape:gccjit_encode_binary()
    local w = writer()
    w.parts[#w.parts + 1] = "LJGJ"
    w:u16(self.version.major)
    w:u16(self.version.minor)
    w:u32(#(self.records or {}))
    for i = 1, #(self.records or {}) do
        local record = self.records[i]
        local payload = writer()
        record:gccjit_tape_write_payload(payload)
        local bytes = payload:finish()
        w:u16(record:gccjit_tape_opcode())
        w:u32(#bytes)
        w.parts[#w.parts + 1] = bytes
    end
    return w:finish()
end
```

## Relationships

Current flow:

```text
source/DSL
  -> prepare_c_artifact / emit_c
  -> frontend_pipeline:
       typecheck
       checked_to_code_result
       code_result_to_c
         computes graph/flow/value/mem/effect/kernel/schedule/lower facts
         lowers to LalinC.CBackendUnit
         validates CBackendUnit
  -> c_emit.emit_artifact(CBackendUnit)  -- C text
  -> compile_c_jit reuses artifact.c_unit
  -> c_gccjit_methods.tape(CBackendUnit)
  -> gccjit_tape binary encoder
  -> c_gccjit.lua FFI
  -> src/lalin_gccjit_bridge.c
  -> libgccjit
```

Important tension:

- `frontend_pipeline.code_result_to_c` already computes optimization facts (`graph`, `flow_facts`, `value_facts`, `mem_semantics`, `effect_facts`, `kernel_plan`, `schedule_plan`, `lower_plan`) before producing `CBackendUnit`.
- GCC-JIT currently receives only `CBackendUnit`; stencil/SOAC/kernel/schedule facts are not preserved into the GCC-JIT request/tape.
- `CBackendUnit` is the right shared semantic lowering target for parity with `emit_c`, but stencil/SOAC vocabulary likely needs to be carried as optional optimization input/provenance beside the unit, not baked into ad hoc tape side tables.
